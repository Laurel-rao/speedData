# FileTransfer

FileTransfer v2：Windows / macOS / Linux 之间传文件和文件夹。**接收端是服务器，发送端主动上传**。

例如 Windows 发送端为 `192.168.100.52`、接收服务器为 `192.168.40.228:8600`：认证、清单、文件分块和进度查询全部由 `100.52 → 40.228:8600` 发起。接收服务器不会回连发送端获取文件；只需发送端能访问服务器，发送端不需要为文件传输入站放行 8600（远程管理发送端页面时另当别论）。

**升级要求：两端都替换为 v2 并重启，不能只升级发送端。** v1 回连推送接口已停用，遇到旧版接收端会明确提示版本不兼容，不会退回双向连接。请先完成或暂停旧任务；旧版本的回连任务索引不直接转换为 v2 上传任务。

- **📤 发送方**：填**接收方的地址 + 密码**（支持粘贴自动识别），选好本地文件或文件夹（可多个、可反复添加），点「发送」直接推过去。
- **📥 接收服务器**：设置**存储目录 + 接收密码**，把「接收地址 + 密码」发给发送方，接收上传后自动校验和落盘。
- **👁 查看进度**：自动复用发送页已填写的接收地址和密码，切换标签即连接；修改发送配置后同步切换监控目标。页面显示当前目标地址，也可点「更改连接」手动查看其他实例。

Go 程序，**编译成独立二进制，双击即用，无需任何运行环境**。

## 使用

**接收方（电脑 B）**
1. 双击 `filetransfer.exe` → 「📥 接收文件」标签。
2. 填存储目录（可选择文件夹）+ 设置接收密码 → 点「**保存并开始接收**」（提示保存成功）。
3. 点「📋 **复制地址+密码**」→ 把复制出的一行字发给发送方。

**发送方（电脑 A / 手机都能用）**
1. 在发送电脑双击 `filetransfer.exe` → 「📤 发送文件」标签。手机只能远程管理运行程序的电脑，不能通过此界面直接上传手机文件。
2. 把收到的「地址+密码」**直接粘贴**到顶部输入框，自动识别填好。
3. 🧪 先点「测试连接」验证通不通 → 用「🗂 选择文件夹…」或「📄 选择文件…」添加要发送的内容（可混合添加多个）→ 勾选「📦 压缩传输」（默认开，接收端自动解压；不勾则逐个文件传）→ 「📤 发送到对方」。
4. 自动传到接收方存储目录，两边实时看进度（待传/传输中/总数，只看前 10 个）。

发送页提供「选择文件夹」和「选择文件」两个按钮，可反复选择并混合添加，也可手动输入一个完整路径（包含分号的文件名不会被拆开）。单独选择的文件直接按文件名保存在接收目录，不会发送同目录的其他文件；文件夹仍保留顶层目录和递归结构。首次发送和追加发送均支持文件，两种压缩模式均适用。同一次请求重复选择同一文件，或同时选择文件夹及其内部文件时只传一次，并优先保留文件夹内的相对路径；不同来源的同名文件会分配保留扩展名的唯一名称。文件选择窗口仍出现在运行程序的电脑上，不是远程管理页面所在的设备。

发送页会单独展示准备进度：扫描文件 → 压缩 → 写入与校验 ZIP → 准备上传 → 已加入传输。压缩阶段按已处理的原始字节计算百分比，同时显示文件数、当前文件和耗时；单个大文件压缩时也会更新。校验阶段显示独立的校验百分比，压缩达到 100% 不代表传输完成。首次发送和追加发送共用此进度，刷新页面可恢复查看本次进程内的准备状态。准备期间禁止重复提交，已在传输的任务不受影响；准备失败保留错误信息，可修正后重试。程序重启后不恢复尚未完成的打包过程。

> 接收服务器须允许发送端访问监听端口；无需允许接收服务器访问发送端端口。控制台窗口别关，关掉即退出。

> 默认监听 `0.0.0.0:8600`。自动打开的本机页面会携带管理授权；手动打开或远程访问页面时，输入默认管理密码 `Admin@981`（不含反斜杠，大小写敏感）。密码内置于程序，重启后不变，与接收密码不同。固定默认密码不具备随机密钥的保密性，请只在可信内网使用，并通过防火墙限制管理访问来源。

> 「选择文件夹」弹窗出现在**运行 FileTransfer 程序的电脑**，不是远程访问网页的手机或另一台电脑。Windows 版使用置顶宿主显示选择窗口；页面等待期间会显示提示并禁止重复点击，超过两分钟自动结束等待。若系统禁用 PowerShell 或没有图形桌面，请在输入框手动填写路径后点「添加」。更新程序需关闭旧进程，替换 exe 后重新打开并刷新页面。

## 特性

| 需求 | 实现 |
|------|------|
| 超大文件 | 4 MiB 分块，4 线程并发；单文件上限 1 TiB |
| 断点续传 | 接收端记录清单与分块，重新提交同一上传任务后复验并仅上传缺失块；压缩包保留解压策略和已完成条目 |
| 文件校验 | 逐块 SHA-256 + 整文件 SHA-256，双层校验，不一致重试 |
| 压缩传输 | **默认开启**：发送方打包成 zip 传输（整包压缩率更高），接收端下载后**自动解压**到目录并清理压缩包；发送时可取消勾选改用逐文件传输 |
| 密码保护 | 接收方设密码，发送方凭密码推送；查看进度也要密码 |
| 连通测试 | 发送前可发一个小测试文件验证地址/密码/链路 |
| 一键连接 | 接收端「📋 复制地址+密码」，发送端直接**粘贴自动识别**填好 |
| 进度信息 | 待传/传输中/总数 计数 + 只看前 10 个在传文件（不刷屏） |
| 文件与文件夹混合发送 | 可反复选择；文件夹保留目录结构，单个文件直接按文件名落盘，同名自动 `(1)` |
| 文件/文件夹选择 | 两个独立按钮；Windows PowerShell 原生弹窗、macOS osascript、Linux zenity/kdialog；均可手动输入路径 |
| 文件名冲突 | 自动重命名 `file (1).txt`（推荐）/ 跳过 / 覆盖；普通文件与压缩包解压遵循同一策略，覆盖不会被同大小拦截 |
| 磁盘预检 | 下载前检查剩余空间，不足直接拒绝 |
| 路径穿越防护 | 拒绝 `..` / 绝对路径 / 盘符 / UNC；使用 os.Root 限定实际读写，阻止符号链接逃逸与 zip-slip |
| 暂停/恢复/取消 | 单文件 + 全部，页面按钮 |
| 自动重试 | 连续失败退避重试 5 次 |
| 时间戳保留 | 落地后保留源文件修改时间 |
| 速率平滑 | 3 秒滑动窗口，速度不跳 |
| 已用时 | 累计任务运行时间（含校验、解压）；全部完成、暂停、取消或失败后停止，追加或恢复任务后继续，不计空闲等待 |
| 传输日志 | `filetransfer.log`（时间/文件/耗时/结果/哈希）+ 页面查看 |
| 临时文件清理 | 只清理带所有权标记的 `.filetransfer-cache` 私有缓存；不按后缀删除业务文件 |
| 完成通知 | 浏览器通知 + 提示音（手机同效） |
| 版本握手 | 连接前交换协议版本，不兼容即提示 |

## 自己编译

### macOS / Linux 运行版

运行文件位于 `dist/`，无需安装 Go：

| 系统 | 文件 |
|------|------|
| Mac Apple Silicon（M 系列） | `filetransfer-darwin-arm64` |
| Mac Intel | `filetransfer-darwin-amd64` |
| Linux x86_64 | `filetransfer-linux-amd64` |
| Linux ARM64 / aarch64 | `filetransfer-linux-arm64` |

在终端进入文件所在目录后运行，例如：

```bash
chmod +x ./filetransfer-darwin-arm64
./filetransfer-darwin-arm64
```

Linux 将命令中的文件名替换为对应 Linux 文件名。默认监听 8600 端口，并尝试打开浏览器；若没有自动打开，手动访问 `http://localhost:8600`。

macOS 文件夹选择使用系统对话框；Linux 图形桌面需要已有 `zenity` 或 `kdialog`，否则在页面手动填写目录。无桌面的 Linux 可运行程序，再从其他电脑浏览器访问 `http://服务器IP:8600`，目录必须填写 Linux 服务器上的路径。程序监听所有网卡，请仅在可信内网使用，不要直接暴露公网。

重新构建以上四个运行文件：

```bash
sh build-unix.sh
```

### Windows 编译

```bash
# 任意装 Go 1.25+ 的机器上
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -ldflags "-s -w" -o filetransfer.exe .
CGO_ENABLED=0 GOOS=windows GOARCH=arm64 go build -ldflags "-s -w" -o filetransfer-arm64.exe .   # Windows on ARM
```

源码：`transfer.go`（发送端、API 与 CLI）、`upload_server.go`（接收服务器上传接口）、`upload_client.go`（主动上传调度）、`receiver.go`（接收校验与恢复）、`storage.go`（安全存储）、`access.go`（管理鉴权与状态汇总）、`index.html`（内嵌页面）。测试：`go test -race -cover ./...`，静态检查：`go vet ./...`。

## v2 恢复与任务控制

- 暂停、继续、取消在接收服务器操作，发送端主动查询状态后执行；旧世代的在途分块不能提交到已取消或重新开始的任务。
- 上传失败后可在接收页继续任务；源文件已变化或不可读时，需要修正源文件，取消旧任务后重新发送。
- 接收服务器重启后，重新配置相同目录和接收密码，仍运行的发送端会重新认证、提交清单并续传。若发送端也退出，则使用相同程序路径与端口，重新添加并发送原目录；不要求接收端访问发送端。
- 正在运行的同一任务重复提交不会重复落盘；已存在文件继续遵循重命名、跳过或覆盖策略。请保留 `.filetransfer-cache`，删除缓存会失去续传进度。

## 安全边界

Windows 发送端遇到 `openat: The parameter is incorrect` 时，会仅针对该错误尝试兼容读取：在读取内容前，根据已打开的目录及文件句柄核验实际路径，拒绝共享目录之外的文件。其他权限错误或越界错误不会触发兼容读取；普通传输和压缩打包共用此检查。

局域网**明文 HTTP**，管理密钥、接收密码与数据均未加密。管理鉴权不是传输加密；仅在可信内网使用，敏感数据应通过 VPN 或 TLS 保护，不要直接暴露公网。

## 其他

- 只传文件不传空目录，目录结构相对路径保留；中文/emoji 文件名 UTF-8。
- 压缩包存入接收端私有缓存，校验后按冲突策略解压；失败可重试，已提交的条目不会回滚。发送端临时压缩包在 Temp 目录。
- 端口默认 8600，接收端可用 `--port` 改。
- 命令行：`filetransfer.exe server --dest D:\接收 --port 8600` 启动服务器页面并预置接收目录，进入页面设置接收密码后开始接收；`pull` 作为原命令别名保留。
- 无桌面运行：`filetransfer.exe pull --no-browser --dest D:\接收`；`serve` 同样支持 `--no-browser`，不自动打开浏览器。
